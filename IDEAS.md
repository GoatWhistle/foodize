## ВЫСОКИЙ ПРИОРИТЕТ

**2. Карта для выбора точки**
Небольшой виджет-карта (не главный экран), открывается по кнопке. Показывает точку/точки сети. Yandex Maps JS API или 2GIS API (оба работают в РФ без VPN). Не делать карту на главном экране при входе.

**28. Оптимизация N+1 запросов**
Частично сделано: `selectinload`/`joinedload` есть в orders, admin, menu, favorites, reviews, staff, vendors. Не покрыт `features/restaurants/crud.py` — список ресторанов грузит категории и рейтинг лениво. Нужен аудит именно там.

**15. Форма заявки на открытие точки (вендор-сайд)**
Бек модерации есть, `VendorApprovalBanner` показывает статус. Нет самой формы подачи заявки с возможностью редактирования до принятия.

**18. Заявки сотрудников — UX**
На беке полный цикл есть, на фронте базовый UI. Нужна нормальная форма с ФИО, номером, почтой и прикреплением резюме + отслеживание статуса.

## СРЕДНИЙ ПРИОРИТЕТ

**30. Оплата через ЮKassa**
Интеграция `yookassa` SDK. Флоу: создать платёж → редирект на страницу оплаты → webhook подтверждение → статус заказа «оплачен». Отправка чека на почту если указана (54-ФЗ через ЮKassa фискализацию).

**13. Сети точек**
Вендор может открыть несколько точек и объединить их в сеть. Карта сети. Единое управление меню (опционально). Требует рефактор модели `Restaurant` — добавить `network_id`, `NetworkGroup`. Большая фича, делать после основного.


**21. Фильтры меню только с реальными категориями**
На странице меню точки показывать только те категории, к которым привязаны товары. Простой фикс на фронте или на беке в запросе категорий.

**25/26. Главная страница — только базовые фильтры**
Убрать фильтр «ищет сотрудников» с главной. Оставить только: шаурма, пицца, бургеры, кофе. Без статусных фильтров. Только открытые точки.

**16. Необязательные ФИО в профиле**
Сделать поля фамилии/отчества опциональными.

## НИЗКИЙ ПРИОРИТЕТ

**32. Карта с точками (глобальная)**
Страница с картой всех открытых точек. Хорошо для discovery. Не срочно если нет масштаба.

**4. Парсинг отзывов с 2ГИС и Яндекс Карт**
Периодический worker (Celery/ARQ), который парсит отзывы по названию/адресу точки и агрегирует с нашими. Юридически серая зона с точки зрения ToS платформ. Технически — selenium или неофициальные API. Реализовывать как отдельный сервис, не в основном бэке.
