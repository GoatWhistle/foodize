## Детальное описание по категориям

### КРИТИЧЕСКИ ВАЖНО (делать в первую очередь)

**19. Адаптация фронта под мобилу**
Основная аудитория — студенты с телефонами. Сейчас фронт не mobile-first. Это блокер для реального использования. Нужен полный responsive-аудит: touch targets 44px+, bottom navigation, убрать hover-only элементы, адаптировать меню/корзину/заказ.

**14. Личный кабинет вендора и сотрудника на фронте**
Сейчас роли есть на беке, но нет нормального UI-входа в ЛК. Должны быть отдельные разделы, доступные через иконку аккаунта в шапке — не через прямой URL. После одобрения заявки вендора автоматически появляется раздел управления точкой.

**22. Иконка аккаунта + выпадающий профиль**
Убрать разбросанные по экрану UI-элементы в единую точку входа — иконка аккаунта справа вверху. В выпадашке: профиль, мои заказы, стать вендором (внизу, не кричит). После одобрения: добавляются пункты управления точкой.

### ВЫСОКИЙ ПРИОРИТЕТ

**1. S3 для фото товаров и ресторана**
Сейчас фото либо нет, либо хранятся в БД/локально. Нужен MinIO (self-hosted) или Cloudflare R2 — загрузка обложки ресторана, фото каждого товара в меню. Без фото карточки товаров мертвые.

**2. Карта для выбора точки**
Небольшой виджет-карта (не главный экран), открывается по кнопке. Показывает точку/точки сети. Интеграция с Yandex Maps JS API или 2GIS API (оба работают в РФ без VPN). Не делать карту на главном экране при входе.

**20. QR-коды на точки**
В профиле каждой точки — кнопка "Показать QR". QR содержит `https://foodize.ru/r/{slug}?ref={restaurant_id}`. Физически распечатывается и вешается в заведении. Открывает сразу нужную точку. Бэк: `qrcode` (Python) или `qr` (JS). Фронт: inline SVG QR.

**24 (доделать). Индикатор работает/не работает**
На основе `working_hours` добавить бейдж "Открыто"/"Закрыто" на карточку ресторана и на страницу точки. Логика на фронте или дополнительный endpoint `GET /restaurants/{id}/is_open`.

**33 (доделать). Визуальная цепочка заказа**
Степпер этапов: "Принят" → "Готовится" → "Готов" → "Выдан". Юзер видит весь путь, не только текущий шаг. В реальном времени через WebSocket (который уже есть).

**31. Фича "заказов перед вами"**
Показывать очередь: N заказов впереди, ориентировочное время ожидания. Считается на беке по количеству активных заказов в точке. Дает уверенность покупателю.

**28. Оптимизация N+1 запросов**
Аудит всех ORM-запросов с `selectinload`/`joinedload` там, где сейчас lazy-load. Особенно критично для: список ресторанов (категории, рейтинг), список товаров (опции), список заказов (items).

### СРЕДНИЙ ПРИОРИТЕТ

**30. Оплата через ЮKassa**
Интеграция `yookassa` SDK. Флоу: создать платёж → редирект на страницу оплаты → webhook подтверждение → статус заказа "оплачен". Отправка чека на почту если указана (54-ФЗ через ЮKassa фискализацию).

**9. Локализация фронта (i18n)**
`react-i18next` или `i18next`. Приоритет: RU/EN. Не срочно, но если планируется масштаб — закладывать сейчас дешевле. Минимальный scope: все строки через `t()`.

**12. Система лояльности**
Каждый ресторан настраивает свои условия: X заказов = бонус (скидка, бесплатный товар). Отдельная таблица `loyalty_programs`, `loyalty_punches`. На фронте — прогресс-бар в карточке точки. Самостоятельный MVP на 1-2 недели.

**13. Сети точек**
Вендор может открыть несколько точек и объединить их в сеть. Карта сети. Единое управление меню (опционально). Требует рефактор модели `Restaurant` — добавить `network_id`, `NetworkGroup`. Большая фича, делать после основного.

**11. Мессенджеры (Telegram и Max)**
Telegram-бот уже есть (`src/telegram-bot/`). Max (VK) — отдельная интеграция через их Bot API. Уведомления о статусе заказа, подтверждения. Max добавлять только если есть реальный спрос.

**4. Парсинг отзывов с 2ГИС и Яндекс Карт**
Нужен периодический worker (Celery/ARQ), который парсит отзывы по названию/адресу точки и агрегирует с нашими. Юридически серая зона с точки зрения ToS платформ. Технически — selenium или их неофициальные API. Реализовывать как отдельный сервис, не в основном бэке.

**5. Пометка "заказ после реального визита"**
Рядом с отзывом — иконка/бейдж если автор оставил отзыв после завершённого заказа через платформу. Простая логика: проверить наличие `order.status == COMPLETED` для этого юзера в этом ресторане. Добавить поле в схему отзыва.

**21. Фильтры меню только с реальными категориями**
На странице меню точки показывать только те категории, к которым привязаны товары. Простой фикс на фронте или на беке в запросе категорий.

**25/26. Главная страница — только базовые фильтры**
Убрать фильтр "ищет сотрудников" с главной. Оставить только: шаурма, пицца, бургеры, кофе. Без статусных фильтров. Только открытые точки.
